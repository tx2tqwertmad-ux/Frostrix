КАК ОПУБЛИКОВАТЬ САЙТ И ПОДГОТОВИТЬ БАЗУ ДАННЫХ
=================================================

ВАЖНО: что сейчас умеет сайт
----------------------------
Это статический HTML/CSS/JavaScript-сайт. После публикации на GitHub Pages страницы будут доступны по публичной ссылке, но сейчас аккаунты, роли, заявки, форум, чат, настройки и статистика сохраняются в localStorage конкретного браузера. Данные не общие для всех посетителей.

Текущая авторизация НЕ является безопасной серверной авторизацией. В коде есть тестовый администратор admin/admin123, а проверка ролей выполняется в браузере. Не используй эту версию для настоящих аккаунтов, приватных данных или реальной административной работы. После подключения базы нужно перенести авторизацию и права доступа на серверную сторону.

ЧАСТЬ 1. Публичная ссылка через GitHub Pages
--------------------------------------------
1. Открой https://github.com и зарегистрируйся/выполни вход.
2. Нажми + → New repository.
3. Назови репозиторий, например server-site. Если выберешь GitHub Free, репозиторий для бесплатного GitHub Pages должен быть публичным.
4. Создай репозиторий (Create repository).
5. Распакуй этот ZIP на компьютере. Открой папку Server-Site-GitHub-Pages.
6. На странице репозитория нажми Add file → Upload files и перетащи ВСЁ СОДЕРЖИМОЕ этой папки, включая index.html, папки css/js/icons, manifest.webmanifest, sw.js и .nojekyll. Важно: загрузи index.html в корень репозитория, а не внутрь дополнительной папки Server-Site.
7. Внизу нажми Commit changes.
8. В репозитории зайди Settings → Pages.
9. В Build and deployment выбери Source: Deploy from a branch. В Branch выбери main и папку /(root), затем нажми Save.
10. Подожди, пока GitHub Pages опубликует сайт; вернись на Settings → Pages и открой Visit site. Обычно адрес имеет вид https://ТВОЙ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/.

Если сайт не открывается, проверь вкладку Actions на ошибку публикации и убедись, что index.html лежит в корне репозитория. Каждый новый Commit changes автоматически запускает обновление опубликованного сайта.

Официальная инструкция GitHub Pages:
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

ЧАСТЬ 2. База данных для этого проекта
--------------------------------------
Рекомендованный вариант: Supabase (PostgreSQL + авторизация). Создай проект на https://supabase.com/ и сохрани Project URL и Publishable key из Project Settings → API Keys. Они нужны для подключения из браузера после настройки политик доступа.

Не публикуй и не присылай никому Database Password, secret key или service_role key. Эти секреты нельзя вставлять в index.html/js-файлы и нельзя класть в публичный GitHub-репозиторий.

Важно: создание проекта Supabase само по себе не подключит эту базу к сайту. Сейчас интерфейс много раз синхронно читает и записывает DB.* и Store/localStorage. Для общей базы потребуется переработать код на асинхронные запросы, заменить локальную авторизацию на Supabase Auth, добавить таблицы и включить RLS-политики для пользователей, заявок, форума/сообщений, настроек и административных действий. Нужно отдельно проверить, что обычный пользователь не сможет выдать себе роль админа.

Рекомендуемый порядок:
1. Сначала опубликуй текущую версию как предварительный просмотр и проверь внешний вид по ссылке.
2. Создай Supabase-проект.
3. Для регистрации через Supabase Auth понадобится email + пароль; текущая форма сайта использует ник + пароль, поэтому её нужно будет изменить и сохранить ник в профиле пользователя.
4. Подключай таблицы только вместе с правилами безопасности (Row Level Security / RLS). Не делай все таблицы доступными для редактирования анонимным посетителям.
5. После интеграции проверь регистрацию, вход, выход, сообщения и права админа в двух разных браузерах/профилях.

Документация Supabase:
https://supabase.com/docs/guides/auth
https://supabase.com/docs/guides/database/secure-data
https://supabase.com/docs/guides/database/postgres/row-level-security

ПРИМЕЧАНИЕ
----------
Этот архив подготовлен для удобной загрузки статического сайта на GitHub Pages: файлы лежат в корне архива и добавлен .nojekyll. Подключение общей базы данных ещё не выполнено намеренно: простой «вставкой ключа» текущий код безопасно и корректно не перевести с localStorage на серверную базу.
